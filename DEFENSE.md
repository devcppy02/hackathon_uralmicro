### Факты, гипотезы и метрики

**Подтверждено кодом и проверками:** задачи сохраняются в SQLite; один ID звонка
не создаёт новые задачи повторно; есть отдельные задачи, статусы, фильтры,
расчёт сроков и добавление типов. Стартовый сценарий с настоящим Qwen включает
10 наших синтетических звонков и 7 ожидаемых задач. Это не все 50 текстов организаторов.

**Пока гипотезы:** обещания будут теряться реже; клиентам потребуется меньше повторных
обращений; оператору понадобится меньше времени на ручное ведение задач.
Не утверждайте конкретное снижение в процентах или экономию в рублях — таких замеров нет.

**Что измерять в пилоте:**

- Доля правильно найденных обещаний среди всех найденных: precision.
- Доля найденных обещаний среди всех обещаний, вручную размеченных человеком: recall.
- Ошибки сроков отдельно от ошибок поиска обещаний.
- Доля задач, закрытых в срок, до и после внедрения на сопоставимых группах.
- Время обработки пачки, доля ошибок и совместимость с тайм-аутом sender.

Покрытие кода тестами не является точностью распознавания обещаний.
Для оценки качества нужна отдельная разметка новых, не использованных при настройке разговоров.

## Одна понятная демонстрация

1. Открыть `/docs`, показать `GET /promise-types`: три стартовых типа.
2. Выполнить PowerShell-пример из README с текущим временем и двумя обещаниями.
   Дождаться ответа Qwen: у задач должны быть разные ID и соответствующие сроки.
3. В `GET /tasks` поставить `operator_id=7` и `status=created`.
4. Для одной задачи выполнить `PATCH`: сначала `in_progress`, затем `completed`.
5. Ещё раз отправить **тот же** JSON звонка: `duplicates=1`, `tasks_created=0`.
6. Показать добавление типа `refund` через `POST /promise-types`.
   Объяснить, что описание начнёт использоваться в новых звонках без изменения кода.
   Распознавание этого типа подтверждено отдельным тестом с реальной моделью.

Для демонстрации просрочки можно отправить отдельный звонок с историческим
`ended_at` и обещанием «перезвоню через час», затем отфильтровать `status=overdue`.
Не меняйте системное время компьютера. Заранее отрепетируйте действия и время ожидания.

## Короткие ответы на вопросы

**Как сервис понимает новый тип?** Название и описание читаются из БД и передаются
Qwen вместе с расшифровкой. Python-код не содержит списка ключевых слов типов.

**Как убедиться, что задача не выдумана?** Сохраняются точная цитата и индекс
реплики оператора; они проверяются перед сохранением. Это защита от выдуманной
цитаты, но не полная гарантия правильного понимания смысла.

**Что при повторе запроса или падении модели?** Повтор уже сохранённого звонка
возвращает существующие задачи. При ошибке модели возвращается `502`, пачка
не сохраняется частично, её можно отправить заново. Автоматического повторителя нет.

**Почему SQLite?** Для мини-проекта одной команды не нужен отдельный сервер БД.
SQLite даёт хранение на диске и транзакции. Масштабирование не реализовано и не
обещается; сначала нужно измерить нагрузку реального пилота.

**Какова точность?** Автотесты и небольшой набор наших размеченных примеров
проходят. Точность на всех 50 разговорах организаторов и на реальных звонках
ещё не измерялась. Нельзя называть её 99,8%: это покрытие кода тестами.

**Что хранится?** Типы обещаний, задачи с цитатами, ID и хеши обработанных звонков.
Исходные полные расшифровки в БД не сохраняются. В кейсе данные синтетические.
