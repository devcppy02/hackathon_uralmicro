# УралМикро · Контроль обещаний

Сервис на Python / FastAPI: принимает расшифровки звонков, выделяет обещания
оператора через локальную Qwen и превращает их в задачи со сроками.

Веб-интерфейс, API и Telegram-бот запускаются **одной командой**. Интерфейс написан
на HTML, CSS и JavaScript, встроен в FastAPI и работает без React, Node.js и CDN.
Данные хранятся в SQLite, отдельный сервер БД не нужен.

## Запуск на Windows

Нужны Python 3.11–3.14 (рекомендуется 3.12) и Git. Команды PowerShell:

```powershell
git clone https://github.com/devcppy02/hackathon_uralmicro.git
cd hackathon_uralmicro
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8080
```

- [Веб-интерфейс](http://localhost:8080/)
- [Swagger API](http://localhost:8080/docs)

Все команды выполняются из корня проекта. Активация окружения и изменение
ExecutionPolicy не нужны. Если ваше окружение называется `venv`, используйте
`venv` вместо `.venv` в путях команд.

Для обновления остановите сервер, выполните `git pull`, повторно установите
`requirements.txt` и запустите ту же команду Uvicorn. Существующий `.env` сохраняйте.
База обновляется автоматически с сохранением прежних задач.

Запускайте **один процесс Uvicorn**, без нескольких workers: он обслуживает
интерфейс, API, polling бота и отправку напоминаний.

| `APP_TIMEZONE` | `Asia/Yekaterinburg` | Часовой пояс календарных сроков и сообщений бота |

LM Studio должен быть доступен с компьютера, на котором запущен FastAPI.
IP в примере не постоянный: при смене сети укажите актуальный адрес компьютера
с моделью. Если API и LM Studio работают на одном ПК, можно указать `http://127.0.0.1:1234/v1`.
При работе по локальной сети включите **Serve on Local Network**. Проверка:

```powershell
curl.exe --noproxy "*" http://172.20.10.6:1234/v1/models
```

Запросы Python к модели идут напрямую, без системных прокси (`trust_env=False`).
Наличие HTML с `403` при доступе через прокси не означает отказ самой модели.
После изменения `.env` перезапустите сервер.

Для обработки новых звонков и поиска подтверждений нужен работающий Qwen.
Просмотр, корректировка, статусы, история, сводка и Telegram работают без модели.
Telegram требует доступа к Интернету.

## Приём звонков от sender

```powershell
.\sender_windows_amd64.exe -t <service_token> -w http://localhost:8080/calls
```

Если sender запущен на другом компьютере, используйте LAN-адрес сервера вместо
`localhost` и разрешите входящие подключения к порту 8080 в брандмауэре Windows.
Формат звонков соответствует [Swagger УралМикро](https://utmn-api.uralmicro.ru/swagger/index.html).

`POST /calls` принимает массив из 1–10 звонков. Обработка синхронная: HTTP-ответ
содержит результат поиска и сохранённые задачи. Для поиска новых обещаний модель
получает пачку одним запросом; для проверки старых обещаний может потребоваться
ещё один запрос. Клиенту нужен тайм-аут, достаточный для обработки моделью.

## Автоматическое создание типов

По умолчанию Qwen использует только существующий справочник. Чтобы разрешить
создание новых категорий, добавьте в `.env` и перезапустите API:

```dotenv
AUTO_CREATE_PROMISE_TYPES=true
```

В этом режиме приоритет остаётся у существующих типов. Договор, справка и выписка
относятся к одному типу отправки документов; разные получатели и сроки не создают
новые категории. Если оператор обещает передать обращение руководству, а подходящей
категории нет, модель может создать общий тип «Передать обращение ответственным».
Такой тип подходит и для передачи обращения профильному отделу.

Каждый предложенный тип проходит отдельную проверку моделью на совпадение по смыслу
с текущим справочником. Если подходит существующий тип, задача получает его.
Проверка требует дополнительного запроса Qwen для каждого нового кандидата,
кроме точного совпадения названия или пустого справочника. При ошибке обработки
новые звонки, задачи и типы не сохраняются; запрос можно повторить.

Новый тип сохраняется сразу, без ручного подтверждения, вместе с задачами в одной
транзакции. Он появляется в разделе «Типы обещаний» и доступен для обычного CRUD.
Поле `types_created` в ответе `POST /calls` содержит добавленные типы; при повторной
отправке того же звонка оно пустое. Параллельные приёмы звонков в этом режиме
обрабатываются последовательно, чтобы видеть уже созданные категории.

Для отключения установите `AUTO_CREATE_PROMISE_TYPES=false` и перезапустите API.
Уже созданные типы остаются в справочнике и используются в обычном режиме.
Проверка снижает вероятность лишних категорий, но не исключает смысловых ошибок модели.

## Веб-интерфейс

- **Задачи:** фильтры по оператору, статусу и диапазону сроков; страницы результатов.
- **Карточка:** исходная цитата, срок, смена статуса, корректировка и история.
- **Сводка:** открытые, просроченные и закрытые задачи по операторам, закрытие в срок.
- **Типы обещаний:** создание, изменение и удаление смысловых описаний.
- **Уведомления:** подключение Telegram и журнал доставки.
- **Приём звонков:** ручная отправка JSON и пример с текущим временем.

Нажмите на задачу для открытия карточки. Исправление текста, типа или срока требует
причины; исходная цитата сохраняется. Автор изменения записывается в историю.
Задачи из предыдущей версии сохраняются, но их история начинается с первого
изменения после обновления.

Интерфейс адаптируется к ширине окна, обновляет задачи каждые 20 секунд и учитывает
системную настройку уменьшения анимаций. Шрифты и ресурсы не загружаются извне.

## Telegram-бот

1. Запишите свой токен в `.env`: `TELEGRAM_BOT_TOKEN=...` и перезапустите сервер.
2. В интерфейсе откройте **Уведомления**, укажите ID оператора, нажмите **Получить код**.
3. Откройте выданную ссылку и нажмите **Запустить**, либо отправьте боту `/start <код>`.

Код одноразовый, действует 10 минут, в БД хранится его хеш. Привязка разрешена
только в личном чате. Один чат связан с одним оператором; новый код позволяет
переподключить оператора. Токен бота не передаётся в браузер и не хранится в Git.

Бот отправляет уведомления о новой задаче, приближении срока, просрочке
и предложении подтвердить выполнение. В сообщениях есть кнопки статусов
и рассмотрения подтверждения. Доступ к чужим задачам через кнопки запрещён.

- `/tasks` — первые 10 открытых задач оператора; полный список доступен в интерфейсе.
- `/stop` — отключить уведомления для этого чата.

Используется aiogram и long polling внутри FastAPI: публичный HTTPS-адрес
и Telegram-вебхук не нужны. Очередь, отправки и повторные попытки сохраняются
в SQLite. Закрытые задачи и устаревшие напоминания пропускаются.
При потере ответа Telegram после фактической отправки возможна повторная доставка.

## Подтверждение по следующему звонку

После приёма звонков сервис ищет открытые задачи того же клиента по нормализованному
телефону. Время подтверждающего звонка должно быть позже исходного.
Проверка учитывает и более ранние звонки, которые поступили с задержкой,
и несколько звонков в одной пачке.

Qwen получает конкретные задачи и разговор. Подтверждение содержит точную цитату,
индекс реплики, автора и объяснение. Идентификаторы и цитата проверяются кодом.
Вопросы, отрицания, новые обещания и другой документ не должны подтверждать задачу.

**Автоматического закрытия нет.** В карточке и Telegram появляется предложение;
человек подтверждает или отклоняет его. Принятие закрывает задачу и записывается
в историю. Корректировка задачи делает старое предложение недействительным.
Повторная обработка уже проверенной пары «задача — звонок» не вызывает модель заново.

Для демонстрации отправьте два звонка с одинаковым телефоном: сначала
«Я отправлю договор», затем более поздний «Да, договор получил». Для сравнения
используйте «Справку получил, а договор не пришёл» — это не подтверждение договора.
В данных sender наличие связанных цепочек звонков не гарантировано.

Старые звонки без сохранённой расшифровки и времени нельзя использовать для
автоматического сопоставления; проверка доступна для звонков, принятых новой версией.

## Методы API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/` | Веб-интерфейс |
| `GET`, `POST` | `/promise-types` | Список и создание типов |
| `GET`, `PUT`, `DELETE` | `/promise-types/{code}` | Чтение, изменение и удаление типа |
| `POST` | `/calls` | Обработка звонков |
| `GET` | `/tasks` | Задачи с фильтрами |
| `GET`, `PATCH` | `/tasks/{id}` | Чтение и смена статуса |
| `PATCH` | `/tasks/{id}/details` | Корректировка с причиной |
| `GET` | `/tasks/{id}/history` | История изменений |
| `GET` | `/summary` | Сводка, необязательный `operator_id` |
| `GET` | `/completion-suggestions` | Предложения: `operator_id`, `status` |
| `POST` | `/completion-suggestions/{id}/review` | Подтвердить или отклонить предложение |
| `GET` | `/telegram/status` | Состояние бота и привязки операторов |
| `POST` | `/telegram/link` | Одноразовый код подключения оператора |
| `GET` | `/notifications` | Журнал: `operator_id`, `limit`, `offset` |

Первоначальные типы: `callback`, `send_documents`, `clarify_and_return`.
Добавление типа требует `code`, `name`, `description`. Для `PUT` — `name` и `description`.
Код неизменяемый, латинские строчные буквы, цифры и `_`, начинается с буквы.
Тип с существующими задачами удалить нельзя (`409`). Описание используется
в новых звонках без изменения Python-кода; старые задачи не пересчитываются.

Пример `PATCH /tasks/{id}/details`:

```json
{
  "title": "Отправить подписанный договор",
  "due_at": "2026-10-30T15:00:00+05:00",
  "reason": "Клиент уточнил документ и согласовал срок",
  "actor": "Анна"
}
```

Можно передать только изменяемые поля: `title`, `type_code`, `due_at`.
Причина обязательна. Закрытые задачи не корректируются.

Пример `POST /completion-suggestions/{id}/review`:

```json
{"accept": true, "actor": "Анна", "reason": "Проверила цитату клиента"}
```

### Сроки, статусы и фильтры

- Сроки считаются от `ended_at`; даты обязательно содержат часовой пояс.
- Простые относительные сроки пересчитываются кодом; календарные и смешанные — Qwen.
- Неизвестный срок — ровно 24 часа после окончания звонка (`default_24h`).
- Дата без времени — 18:00; конец дня — 23:59:59; конец рабочего дня — 18:00.
- Источник срока: `explicit`, `default_24h` или `manual` после ручного изменения.
- Статусы: `created` → `in_progress` → `completed`. Истечение срока даёт `overdue`.
- Из `overdue` можно закрыть задачу. Подтверждение выполнения по цитате также
  может закрыть открытую задачу с отдельной записью в истории.
- Перенос просроченного срока в будущее возвращает задачу в `in_progress`.
- Сводка считает своевременность по времени отметки закрытия, а не по фактической
  дате исполнения, которую сервис не может независимо подтвердить.

Фильтры `/tasks`: `status`, `operator_id`, `due_from`, `due_to`, `limit` (1–500),
`offset`. Границы срока включительны, сортировка по сроку и ID.
Ответ: `items`, `total`, `limit`, `offset`. Даты возвращаются в UTC.

### Повторы и ошибки

Один ID звонка создаёт задачи один раз. Повтор возвращает существующие задачи;
изменённое содержимое с прежним ID — `409`. Разные ID остаются разными звонками.

Ошибка основного поиска обещаний даёт `502`, звонки не сохраняются частично.
Если задачи уже сохранены, но дополнительная проверка выполнения не удалась,
ответ содержит `warnings`. Повтор того же запроса безопасно повторит незавершённую
проверку, не создавая новые задачи.

Неверные данные — `422`, отсутствующий объект — `404`, недопустимое изменение
статуса/типа или повторное рассмотрение предложения — `409`.

## Демонстрация в PowerShell

Пример создаёт две задачи, закрывает одну и проверяет повтор без дублей.
Выполните весь блок целиком; при первой ошибке он остановится.

```powershell
& {
    $ErrorActionPreference = "Stop"
    $base = "http://localhost:8080"
    $end = [DateTimeOffset]::Now
    $call = @{
        id = [guid]::NewGuid().ToString()
        operator_id = 7
        client_phone = "+70000000000"
        started_at = $end.AddMinutes(-5).ToString("o")
        ended_at = $end.ToString("o")
        transcript = @(
            @{ speaker = "client"; text = "Мне нужен договор." }
            @{ speaker = "operator"; text = "Договор вышлю через час. Перезвоню через два часа." }
        )
    }
    $json = ConvertTo-Json -InputObject @($call) -Depth 6
    $body = [System.Text.Encoding]::UTF8.GetBytes($json)
    $result = Invoke-RestMethod -Method Post -Uri "$base/calls" `
        -ContentType "application/json; charset=utf-8" -Body $body -TimeoutSec 300
    if (@($result.tasks).Count -ne 2) { throw "Ожидались две задачи" }
    $result.tasks | Format-Table id, type_code, due_at, status
    $taskId = $result.tasks[0].id
    Invoke-RestMethod -Method Patch -Uri "$base/tasks/$taskId" `
        -ContentType "application/json" -Body '{"status":"in_progress"}'
    Invoke-RestMethod -Method Patch -Uri "$base/tasks/$taskId" `
        -ContentType "application/json" -Body '{"status":"completed"}'
    $repeat = Invoke-RestMethod -Method Post -Uri "$base/calls" `
        -ContentType "application/json; charset=utf-8" -Body $body -TimeoutSec 300
    if ($repeat.duplicates -ne 1 -or $repeat.tasks_created -ne 0) {
        throw "Повтор должен вернуть duplicates=1, tasks_created=0"
    }
    $repeat | Select-Object processed, duplicates, tasks_created
}
```

## Устройство и ограничения

- `app/api.py` — HTTP-маршруты и запуск служб.
- `app/static/` — встроенный интерфейс.
- `app/storage.py`, `app/migrations.py` — SQLite и обновление схемы.
- `app/workflow.py` — корректировки, история, сводка и рассмотрение подтверждений.
- `app/llm.py`, `app/completion.py`, `app/deadlines.py` — обработка разговоров и сроков.
- `app/notifications.py`, `app/bot.py` — постоянная очередь и aiogram.

Это локальный прототип одной команды без авторизации пользователей веб-интерфейса
и API; поле автора корректировки — запись в журнале, а не проверка личности.
Модель может ошибаться в смысле и датах. Проверка цитат не гарантирует правильную
классификацию; окончательное решение о выполнении принимает человек.

Новые звонки сохраняются с расшифровками и временем для сопоставления последующих
обращений. Данные кейса синтетические. База и токен бота не включаются в Git.
При настроенном Telegram просрочка проверяется также фоновым циклом;
без бота — при обращении к задачам и журналу.

Для чистой демонстрации остановите сервер и удалите `data`. Это удалит также
историю, очередь уведомлений и привязки Telegram. Оператора нужно будет подключить заново.

ИИ-инструмент разработки: Codex (OpenAI) — проектирование, написание кода и тестов.
